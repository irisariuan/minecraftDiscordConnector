# Proxy ↔ Bot control API

The Go proxy (`plugins/minecraft/proxy`) is a child process of the bot. It owns
no database, no Discord connection and no credentials: every decision that needs
the bot's state is asked over this small HTTP API, which the bot serves over a
Unix domain socket rather than a network port.

- **Transport** HTTP over the Unix socket at `${MC_PROXY_IPC_PATH}` (default
  `data/mcproxy.sock`), created mode 0600. There is no listening port, so the
  channel is reachable only by a process that can open that file. Requests carry
  `Host: mcproxy.ipc`, which is a placeholder and is not routed on.
- **Auth** every request carries `Authorization: Bearer <token>`, where the token
  is `MC_PROXY_TOKEN` or, when unset, a random token generated by the bot at
  startup and handed to the child through its environment. A request without the
  correct token gets `401` and is not processed.
- **Encoding** JSON request and response bodies, UTF-8.
- **Binding** the bot MUST serve this on a Unix socket, never a network port.

All UUIDs on this API are lowercase and dashed.

---

## `GET /config`

Polled by the proxy every 2 seconds. It is the proxy's only source of truth for
which backends exist and whether they are up.

**Response `200`**

```json
{
  "listenPort": 25565,
  "publicHost": "mc.example.com",
  "maxPlayers": 100,
  "motd": "§bServer Hub§r\n§7Join to start a server",
  "linkTtlSeconds": 300,
  "voteChannelConfigured": true,
  "servers": [
    {
      "id": 1,
      "tag": "Survival",
      "host": "127.0.0.1",
      "port": 25566,
      "online": true,
      "forwarding": "bungeecord",
      "forwardingSecret": null
    }
  ]
}
```

- `publicHost` is the address clients use to reach the proxy. It is currently
  reserved: the proxy reads it but does not act on it, and it exists for a future
  hand-off that moves a player between backends mid-session. The bot sends `""`
  when nothing is configured.
- `motd` uses legacy `§` colour codes and may contain one `\n`.
- `servers` lists only servers whose plugin is `minecraft` and whose
  `config.proxy.enabled` is true. `online` is live process state.
- `forwarding` is one of `"none"`, `"bungeecord"`, `"velocity"`.
  `forwardingSecret` is non-null only for `"velocity"`.

## `POST /session`

Called once per login, after the proxy has authenticated the player against
Mojang. Tells the proxy who this player is and what they may do.

**Request**

```json
{ "uuid": "…", "name": "Notch", "ip": "1.2.3.4", "protocol": 767 }
```

**Response `200`**

```json
{
  "linked": true,
  "discordId": "123456789",
  "voteChannelConfigured": true,
  "servers": [
    {
      "id": 1,
      "tag": "Survival",
      "online": false,
      "accessible": true,
      "canStart": true,
      "pollPending": false,
      "pollUrl": null
    }
  ]
}
```

- `accessible` applies the core per-server access list. For an unlinked player
  `linked` is false, `discordId` is absent and every `accessible` is false.
- `canStart` means the linked user holds the `startServer` permission, so a start
  would happen immediately rather than through a vote.
- `pollPending` means a start vote for that server is already open;
  `pollUrl` links to it when known.

## `POST /start`

The player asked, in game, for a server to be started.

**Request**

```json
{ "uuid": "…", "name": "Notch", "serverId": 1 }
```

**Response `200`**

```json
{ "status": "poll_created", "message": "A vote to start Survival was posted.", "pollUrl": "https://discord.com/…" }
```

`status` is one of:

| status | meaning |
| --- | --- |
| `started` | the server is starting now |
| `already_online` | nothing to do, the proxy should route the player |
| `poll_created` | a vote was posted to the configured channel |
| `poll_pending` | a vote is already open; the player should wait or vote |
| `no_channel` | no vote channel configured, so the player must start a vote on Discord |
| `no_permission` | not allowed and no vote could be raised |
| `insufficient_credit` | the linked account could not pay the poll fee |
| `port_conflict` | another server already holds the port |
| `not_linked` | the player has no linked Discord account |
| `no_access` | the linked account may not use this server |
| `failed` | anything else; `message` explains |

`message` is safe to show verbatim in game. It must be plain text, no `§` codes,
no newlines.

## `POST /link/begin`

An unlinked player tried to join. The proxy issues them a code and puts it into
the disconnect message, so they can finish the link on Discord with `/linkcode`
and come straight back.

**Request** `{ "uuid": "…", "name": "Notch" }`

**Response `200`** `{ "code": "123456", "expiresInSeconds": 300 }`

**Response `409`** `{ "error": "already_linked" }`

The bot keeps the pending code in memory only. A code is six digits, single use,
and expires after `linkTtlSeconds`.
